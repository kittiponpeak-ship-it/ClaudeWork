# CS2 Match Tracker

เว็บบันทึกสถิติ CS2 รายแมตช์ — HTML + CSS + JavaScript ล้วน ไม่มี framework ไม่มี backend

## สถานะ: ครบทั้ง 14 ขั้น ✅

| ขั้น | ได้อะไร |
|---|---|
| 1 ✅ | ฟอร์มกรอก + ตรวจข้อมูล + `console.log` |
| 2 ✅ | เซฟเป็น array ของ object ลง `localStorage` — refresh แล้วข้อมูลไม่หาย |
| 3 ✅ | ตารางประวัติ เรียงล่าสุดขึ้นก่อน + ลบทีละแถว |
| 4 ✅ | กราฟเทรนด์ ADR / K/D / HS% ด้วย Chart.js (CDN) พร้อมเส้นค่าเฉลี่ย |
| 5 ✅ | กรองตาม map, สรุป win rate + ค่าเฉลี่ย, เช็กลิสต์ซ้อมรายสัปดาห์ |
| 6–7 ✅ | แก้ไขแมตช์ที่กรอกผิด, validation กันค่าติดลบ, จัด layout, เก็บ edge case |
| 8 ✅ | Trend indicator — เทียบ 5 แมตช์ล่าสุดกับ 5 แมตช์ก่อนหน้า ขึ้นลูกศรเขียว/แดง |
| 9 ✅ | Best / Worst map — จัดกลุ่มตาม map แล้วเทียบ win rate (นับเฉพาะแมพที่เล่นครบ 3 แมตช์) |
| 10 ✅ | ตั้งเป้า ADR / K/D / HS% + แถบความคืบหน้า |
| 11 ✅ | Streak — ชนะ/แพ้ติดกันกี่แมตช์ |
| 12 ✅ | Export / Import ข้อมูลเป็นไฟล์ JSON |
| 13 ✅ | Responsive เต็มรูปแบบ + ปุ่มสลับธีมมืด/สว่าง (จำค่าไว้) |
| 14 ✅ | พร้อม deploy ขึ้น GitHub Pages (ดูหัวข้อล่างสุด) |

## วิธีเปิด

ดับเบิลคลิก `index.html` ได้เลย หรือถ้าอยากเปิดผ่าน local server:

```bash
cd cs2-stats
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000
```

เปิด DevTools (F12) แท็บ Console เพื่อดูผลลัพธ์ของ `console.log` / `console.table`

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าเว็บ + ฟอร์ม (แต่ละช่องมี `name` ไว้ให้ `FormData` ดึงค่า) |
| `style.css` | สีทั้งหมดอยู่ในตัวแปร CSS ที่ `:root` — ธีมมืด/สว่างจึงแค่สลับค่าตัวแปร |
| `theme.js` | ปุ่มสลับธีม + จำค่าไว้ใน localStorage |
| `insights.js` | เทรนด์ฟอร์ม (ขั้น 8), map ถนัด/ต้องซ้อม (ขั้น 9), สตรีค (ขั้น 11) |
| `goals.js` | เป้าหมาย + แถบความคืบหน้า (ขั้น 10) |
| `backup.js` | Export / Import ไฟล์ JSON (ขั้น 12) |
| `app.js` | ฟอร์ม → ตรวจข้อมูล → เซฟลง localStorage → สั่งวาดทุกส่วนผ่าน `render()` |
| `practice.js` | เช็กลิสต์ซ้อมรายสัปดาห์ (แยกไฟล์ เพราะใช้ storage คนละ key) |

**ลำดับ `<script>` สำคัญ**: `theme.js` → `insights.js` → `goals.js` → `backup.js` → `app.js` → `practice.js`
เพราะ `app.js` เรียก `renderTrend()` / `renderMapBoards()` / `renderGoals()` ตั้งแต่ตอนวาดหน้าครั้งแรก
ไฟล์ที่นิยามฟังก์ชันพวกนี้จึงต้องถูกโหลดก่อน (ทุกไฟล์เป็น script ธรรมดา ไม่ใช่ ES module
ฟังก์ชันระดับบนสุดจึงเป็น global ใช้ข้ามไฟล์ได้ — แต่ต้องระวังตั้งชื่อ `const` ซ้ำกัน เพราะจะพังทันที)

## ข้อมูลที่เก็บต่อ 1 แมตช์

```js
{
  id: 1755000000000,   // Date.now() ไว้อ้างอิงตอน Milestone 2–3
  date: "2026-08-26",  // YYYY-MM-DD
  map: "Mirage",
  kills: 24,
  deaths: 16,
  kd: 1.5,             // คำนวณจาก kills / deaths ให้อัตโนมัติ
  adr: 92.4,
  hs: 58.3,            // เปอร์เซ็นต์ 0–100
  result: "win",       // "win" | "loss" | "draw"
  savedAt: "2026-08-26T03:54:03.050Z",  // เวลาที่กดบันทึกครั้งแรก
  editedAt: "2026-08-26T04:23:36.979Z"  // มีเฉพาะแมตช์ที่เคยกดแก้ไข
}
```

ทั้งหมดถูกเก็บเป็น **array** ใต้ key `cs2-matches` ใน localStorage
ส่วนที่เหลือแยก key กันคนละอัน — `cs2-goals` (เป้าหมาย), `cs2-practice` (เช็กลิสต์ซ้อม),
`cs2-theme` (ธีมที่เลือกไว้):

```js
[ { …แมตช์ที่ 1… }, { …แมตช์ที่ 2… } ]
```

ดูของจริงได้ที่ DevTools → แท็บ **Application** → Local Storage → เลือก origin ของหน้าเว็บ
หรือพิมพ์ในแท็บ Console:

```js
JSON.parse(localStorage.getItem('cs2-matches'))
```

## จุดที่ตั้งใจทำใน Milestone 1

- `event.preventDefault()` กันหน้า reload ตอน submit
- ใช้ `FormData` ดึงค่าทุกช่องทีเดียว แทนการ `getElementById` ทีละอัน
- ค่าจากฟอร์มเป็น **string เสมอ** → แปลงด้วย `Number()` ก่อนใช้คำนวณ
- ตรวจข้อมูลเอง (`novalidate`) เพื่อคุมข้อความ error ภาษาไทยได้
- `deaths = 0` ไม่ทำให้ K/D กลายเป็น `Infinity` — ใช้จำนวน kills แทน
- วันที่ default เป็นวันนี้ และเลือกวันในอนาคตไม่ได้

## จุดที่ตั้งใจทำใน Milestone 2

- localStorage เก็บได้แต่ **ข้อความ** → เซฟด้วย `JSON.stringify`, อ่านด้วย `JSON.parse`
- ไม่มีคำสั่ง "เพิ่มทีละตัว" → ต้อง **อ่าน array เดิม → `push` → เขียนกลับทั้งก้อน**
- `getItem` คืน `null` ถ้ายังไม่เคยเซฟ — ต้องเผื่อกรณีนี้ ไม่งั้น `JSON.parse(null)` พัง
- ครอบ `try/catch` ทั้งตอนอ่านและตอนเขียน: ข้อมูลใน storage พังก็ยังเปิดหน้าเว็บได้
  (คืน array ว่างแทนการ crash) และเซฟไม่ได้ก็ขึ้นคำเตือนแทนที่จะเงียบ
- เช็คก่อนว่าเบราว์เซอร์ให้ใช้ localStorage ไหม (โหมดส่วนตัวบางตัวห้าม)
- `id` กันซ้ำ เผื่อกด submit สองครั้งในมิลลิวินาทีเดียวกัน — จะได้ใช้อ้างอิงตอนลบใน Milestone 3

## จุดที่ตั้งใจทำใน Milestone 3

- **วาดใหม่ทั้งตารางทุกครั้งที่ข้อมูลเปลี่ยน** ผ่านฟังก์ชัน `render()` ตัวเดียว
  (โหลด/เพิ่ม/ลบ/ล้าง เรียกตัวเดียวกันหมด) — คิดง่ายกว่าไล่แก้ DOM ทีละจุด
- **event delegation** — ผูก `click` ไว้ที่ `<tbody>` ตัวเดียว แล้วดูว่าคลิกโดนปุ่มลบไหม
  แทนการผูก listener ทีละปุ่ม แถวที่วาดใหม่ทีหลังก็ใช้ได้เลย
- ปุ่มลบฝัง `data-id` ไว้ อ่านกลับด้วย `button.dataset.id` (ได้เป็น string ต้อง `Number()` ก่อนเทียบ)
- `sort()` **แก้ array ตัวเดิม** เลยก็อปด้วย `[...matches]` ก่อนเรียง จะได้ไม่ไปสลับลำดับที่เซฟไว้
- วันที่รูปแบบ `'YYYY-MM-DD'` เทียบกันแบบ string ได้เลย ไม่ต้องแปลงเป็น `Date`
- สร้างแถวด้วย `createElement` + `textContent` (ไม่ใช่ `innerHTML`) — ข้อความแปลก ๆ
  จะได้ไม่ถูกตีความเป็น HTML
- ⚠️ บทเรียนจากบั๊กจริงตอนทำขั้นนี้: `const` ที่ประกาศไว้ **ล่างไฟล์** แต่ถูกเรียกใช้ตอนหน้าโหลด
  จะพัง (temporal dead zone) ต่างจาก `function` ที่ถูกยกขึ้นไปบนสุดให้อัตโนมัติ (hoisting)
  → ค่าคงที่ที่ใช้ตอนเริ่มต้นต้องประกาศไว้ก่อนถูกเรียก

## จุดที่ตั้งใจทำใน Milestone 4 (กราฟ)

- Chart.js ใส่ผ่าน CDN บรรทัดเดียว ต้องวาง `<script>` ของมัน **ก่อน** `app.js`
- ถ้าเน็ตหลุด/CDN โหลดไม่ติด → เช็ค `typeof Chart === 'undefined'` แล้วขึ้นข้อความแทน
  ส่วนอื่นของหน้ายังใช้ได้ตามปกติ
- ตารางเรียงใหม่→เก่า แต่กราฟต้องเรียง **เก่า→ใหม่** ถึงจะอ่านเป็นเทรนด์ได้
- เส้นค่าเฉลี่ยคือ dataset ที่สอง — ค่าเดิมซ้ำทุกจุด ก็ได้เส้นตรงแนวนอน ไม่ต้องใช้ plugin
- สร้าง chart ครั้งเดียวแล้วใช้ `chart.update()` ตอนข้อมูลเปลี่ยน (ไม่ใช่ `new Chart` ซ้ำ ๆ)
- `maintainAspectRatio: false` ต้องคู่กับกล่องที่กำหนดความสูงไว้ใน CSS (`.chart-box`)
- 💡 กราฟมี animation ตอนเริ่ม ~1 วิ ถ้าวัดตำแหน่งจุดทันทีจะได้ค่าระหว่างทาง ไม่ใช่ค่าจริง

## จุดที่ตั้งใจทำใน Milestone 5 (ตัวกรอง / สรุป / เช็กลิสต์)

- ตัวกรองเป็น **แหล่งความจริงเดียว**: `render()` กรองข้อมูลก่อน แล้วส่งชุดเดียวกันให้
  สรุป กราฟ และตาราง — ทั้งสามส่วนตรงกันเสมอ
- ตัวเลือกใน dropdown สร้างจาก map ที่มีอยู่จริงในข้อมูล ถ้าลบจนหมดจะเด้งกลับเป็น "ทุก map"
- เช็กลิสต์เก็บแยกที่ key `cs2-practice` รูปแบบ `{ week: '2026-W35', done: [...] }`
  — เก็บรหัสสัปดาห์ไว้ด้วย พอข้ามสัปดาห์ก็รู้ว่าต้องเริ่มนับใหม่ (รีเซ็ตอัตโนมัติทุกวันจันทร์)
- รหัสสัปดาห์ใช้แบบ ISO (สัปดาห์เริ่มวันจันทร์ ตัดสินปีด้วยวันพฤหัส) ต้นปี/ปลายปีถึงจะไม่เพี้ยน
- `id` ของแต่ละข้อในเช็กลิสต์ห้ามเปลี่ยนทีหลัง ไม่งั้นที่ติ๊กไว้จะจำไม่ได้

## จุดที่ตั้งใจทำในข้อ 6–7 (ฟีเจอร์เสริม + polish)

**แก้ไขแมตช์ที่กรอกผิด** — กดปุ่ม ✎ ท้ายแถว ข้อมูลจะเด้งกลับขึ้นไปในฟอร์ม
ฟอร์มขึ้นขอบส้มบอกว่ากำลัง "แก้ของเดิม" ไม่ใช่ "เพิ่มใหม่" และแถวที่กำลังแก้จะไฮไลต์ไว้

- ใช้ฟอร์มเดิมทำทั้งสองอย่าง โดยจำสถานะไว้ในตัวแปรเดียว: `editingId`
  (`null` = เพิ่มใหม่ / เป็นตัวเลข = กำลังแก้แมตช์ไอดีนั้น)
- ตอนเซฟ: ถ้ากำลังแก้อยู่ ให้หา index แล้วเขียนทับด้วย `{ ...ของเดิม, ...ค่าใหม่ }`
  — **คง `id` กับ `savedAt` เดิมไว้** แล้วเติม `editedAt` ต่างหาก
- ปุ่มแก้กับปุ่มลบใช้ตัวจัดการคลิกที่ `<tbody>` ตัวเดียวกัน แยกด้วย `classList.contains()`
- เคสที่ต้องกันไว้: ลบแมตช์ที่กำลังแก้อยู่ / กดล้างข้อมูลทั้งหมดระหว่างแก้ / แมตช์หายไปจากอีกแท็บ
  → ออกจากโหมดแก้ไขให้อัตโนมัติ (เคสสุดท้ายเซฟเป็นแมตช์ใหม่แทน ไม่ไปทับข้อมูลใคร)

**validation** — ข้อความบอกตรง ๆ ว่าผิดตรงไหน: `ADR ติดลบไม่ได้`, `HS% ต้องไม่เกิน 100`,
`Kills ต้องเป็นจำนวนเต็ม` และพอพิมพ์แก้ช่องไหน error ของช่องนั้นหายทันทีไม่ต้องรอกดบันทึก

- `min="0"` ใน HTML แค่ช่วยเรื่องปุ่มลูกศร **กันไม่ได้จริง** (พิมพ์เองหรือวางทับได้) → ต้องเช็คใน JS ซ้ำ
- ช่อง `type="number"` ถ้าพิมพ์ตัวอักษรลงไป เบราว์เซอร์ส่งค่าว่างมาให้ เลยรวมกับเคส "ไม่ได้กรอก" ได้เลย

**layout** — จอกว้าง ≥ 980px แบ่งเป็นฟอร์มซ้าย (ลอยติดตามเวลาเลื่อน ถ้าจอสูงพอ) / สรุป-กราฟ-ตาราง-เช็กลิสต์ขวา
จอแคบยุบเป็นคอลัมน์เดียวเรียงตามลำดับการใช้งาน

- `minmax(0, 1fr)` ในคอลัมน์ขวาสำคัญมาก ไม่งั้นตารางที่กว้างเกินจะดันคอลัมน์ให้บานออกนอกจอ
- ระยะห่างการ์ดใช้ `gap` ที่คอนเทนเนอร์ที่เดียว ไม่ต้องใส่ `margin-bottom` ทีละใบ
- `position: sticky` ใส่ใน media query ที่เช็ค `min-height` ด้วย ไม่งั้นจอเตี้ยจะเลื่อนดูท้ายฟอร์มไม่ได้

**edge case ที่เทสต์แล้ว** — ยังไม่มีข้อมูลสักแมตช์: ทั้งสามส่วนขึ้นข้อความบอกว่าให้ทำอะไรต่อ
(ไม่ใช่กล่องเปล่า ๆ) ตัวกรองกับปุ่มล้างข้อมูลถูกปิดไว้ / กรองแล้วไม่เจอ: ขึ้น `ยังไม่มีแมตช์ของ Nuke`
แยกจากกรณีไม่มีข้อมูลเลย / เน็ตหลุด: กราฟขึ้นข้อความแทน ส่วนอื่นใช้ได้ครบ

## จุดที่ตั้งใจทำในขั้น 8–11 (ตัวเลขที่ "อ่านแล้วรู้ว่าต้องทำอะไรต่อ")

ทั้งสามอย่างนี้ไม่ได้เก็บข้อมูลเพิ่มเลย — คำนวณสดจากแมตช์ที่มีอยู่แล้วทุกครั้งที่ `render()`

**ขั้น 8 — เทรนด์ฟอร์ม** เรียงใหม่→เก่า แล้ว `slice(0, 5)` กับ `slice(5, 10)` เทียบค่าเฉลี่ยกัน

- ต้องมีอย่างน้อย 7 แมตช์ถึงจะเริ่มเทียบ (กลุ่มก่อนหน้าต้องมี ≥ 2 แมตช์)
  น้อยกว่านั้นขึ้นข้อความบอกว่าเหลืออีกกี่แมตช์ ดีกว่าโชว์ลูกศรที่เชื่อไม่ได้
- **ปัดทศนิยมก่อน แล้วค่อยตัดสินว่าขึ้นหรือลง** ไม่งั้นส่วนต่าง 0.04 จะขึ้นลูกศรเขียว
  ทั้งที่บนจอโชว์ `+0.0` — ตัวเลขกับสีต้องเล่าเรื่องเดียวกัน

**ขั้น 9 — map ถนัด / ต้องซ้อม** จับกลุ่มด้วย object (key = ชื่อ map) แล้ว `Object.values()` แปลงกลับเป็น array

- แมพที่เล่นไม่ถึง 3 แมตช์ **ไม่เอามาตัดสิน** — ชนะ 1 จาก 1 แมตช์ไม่ได้แปลว่าถนัด
  แต่ยังบอกไว้ด้านล่างว่าเหลืออีกกี่แมตช์ถึงจะนับ จะได้ไม่งงว่าทำไมแมพนั้นไม่ขึ้น
- ต้องมีอย่างน้อย 2 แมพที่ครบเกณฑ์ถึงจะเทียบกันได้
- ส่วนนี้ดู **ทุกแมตช์เสมอ** ไม่สนตัวกรอง map ด้านบน เพราะจุดประสงค์คือเทียบแมพกันเอง
  (ถ้ากรองเหลือแมพเดียวก็ไม่มีอะไรให้เทียบ)

**ขั้น 11 — สตรีค** ไล่จากแมตช์ล่าสุดย้อนกลับ เจอผลที่ต่างออกไปเมื่อไหร่ `break` ทันที

## จุดที่ตั้งใจทำในขั้น 10 (เป้าหมาย)

- เว้นช่องว่าง = **ไม่ตั้งเป้าตัวนั้น** ไม่ใช่ error — จะตั้งแค่ ADR อย่างเดียวก็ได้
- ความคืบหน้า = ค่าเฉลี่ยจริง ÷ เป้า × 100 — ตัวเลขโชว์เกิน 100% ได้ (เช่น 133%)
  แต่ **แถบตันที่ 100%** ไม่งั้นแถบจะล้นออกนอกกล่อง
- ค่าเฉลี่ยที่เอามาเทียบใช้ชุดเดียวกับที่ตัวกรอง map เลือกอยู่ เลยตั้งเป้าเฉพาะแมพได้ด้วย
  (มีข้อความกำกับไว้ว่ากำลังคิดจากกี่แมตช์)
- ตอนอ่านค่าจาก localStorage กรองซ้ำอีกรอบว่าเป็นตัวเลขบวกและไม่เกินเพดาน
  เผื่อไฟล์ที่ import เข้ามาถูกแก้มา

## จุดที่ตั้งใจทำในขั้น 12 (Export / Import)

- เบราว์เซอร์ดาวน์โหลดได้เฉพาะไฟล์ที่ "มี URL" → ห่อข้อความเป็น `Blob`
  แล้วขอ URL ชั่วคราวด้วย `URL.createObjectURL()` และ **`revokeObjectURL()` ทิ้งหลังใช้เสร็จ**
- ไฟล์เดียวเก็บครบทุก key: แมตช์ + เป้าหมาย + เช็กลิสต์ + ธีม
- `<input type="file">` ซ่อนไว้ ใช้ปุ่มปกติกด `.click()` แทน จะได้จัดสไตล์ได้
- **ต้องเคลียร์ `input.value` หลังอ่านไฟล์เสร็จ** ไม่งั้นเลือกไฟล์เดิมซ้ำอีกครั้ง
  event `change` จะไม่ยิง (เพราะค่าไม่เปลี่ยน)
- ข้อมูลจากไฟล์ = ข้อมูลจากข้างนอก → ตรวจทุกแถวก่อนเขียนลง localStorage
  วันที่ผิดรูปแบบ / ค่าติดลบ / `result` ที่ไม่รู้จัก → ข้ามแถวนั้นแล้วบอกว่าข้ามไปกี่แถว
  ส่วน `id` ที่ซ้ำกันต้องออกใหม่ ไม่งั้นปุ่มแก้ไข/ลบจะไปโดนแถวผิด และ `kd` คำนวณใหม่เสมอ

## จุดที่ตั้งใจทำในขั้น 13 (ธีม + มือถือ)

- สีทุกสีอยู่ในตัวแปร CSS ที่ `:root` การสลับธีมจึงเป็นแค่การเปลี่ยนค่าตัวแปรชุดเดียว
  ไม่ต้องไล่แก้ทีละกฎ — ธีมสว่างอยู่ในบล็อก `:root[data-theme="light"]` บล็อกเดียว
- ค่าเริ่มต้นคือ **ธีมมืด** จะสว่างก็ต่อเมื่อกดปุ่มเลือกเอง
- มี `<script>` สั้น ๆ ใน `<head>` อ่านค่าจาก localStorage แล้วใส่ `data-theme` ทันที
  **ก่อนหน้าจะวาด** ไม่งั้นจะเห็นจอมืดแวบหนึ่งก่อนเปลี่ยนเป็นสว่างทุกครั้งที่โหลด
- `color-scheme` ทำให้ปฏิทิน/แถบเลื่อน/checkbox ของเบราว์เซอร์เปลี่ยนโทนตามไปด้วย
- Chart.js วาดลง `<canvas>` เป็นรูปภาพ **มันไม่รับสีจาก CSS เอง** → ต้องอ่านค่าตัวแปรด้วย
  `getComputedStyle()` แล้วป้อนให้ พร้อมสั่งวาดใหม่ทุกครั้งที่สลับธีม
- ⚠️ บั๊กจริงที่เจอตอนทำขั้นนี้: `.sr-only` ในหัวตารางเป็น `position: absolute`
  ถ้ากล่องที่ครอบไม่ได้ตั้ง `position: relative` มันจะไปอิงกับทั้งหน้าแทนแล้วหลุดออกนอกจอ
  ทำให้หน้าเลื่อนซ้าย-ขวาได้ทั้งหน้าบนมือถือ
- อีกจุด: grid item ปกติ **หดแคบกว่าเนื้อหาข้างในไม่ได้** ตารางที่ตั้ง `white-space: nowrap`
  เลยดันคอลัมน์ให้บานเกินจอ → ต้องใส่ `min-width: 0` ให้ item ทุกชั้น

### ข้อควรรู้เรื่อง localStorage

- ผูกกับ **origin** — เปิดด้วย `file://` กับ `http://localhost:8000` จะเห็นคนละชุด
- อยู่แค่ **เครื่องนี้ เบราว์เซอร์นี้** ไม่ sync ข้ามเครื่อง และหายถ้าล้าง browsing data
- เก็บได้ราว 5 MB ต่อ origin — สถิติ CS2 แบบนี้เก็บได้เป็นหมื่นแมตช์ สบาย ๆ

## ขั้น 14 — เอาขึ้นเว็บจริงด้วย GitHub Pages

โค้ดอยู่บน GitHub แล้ว เหลือแค่เปิดสวิตช์ Pages ซึ่งต้องทำในหน้าเว็บ GitHub เอง:

1. เข้า repo → **Settings** → **Pages** (เมนูซ้ายมือ)
2. **Source**: เลือก *Deploy from a branch*
3. **Branch**: เลือก branch ที่ merge เข้า `main` แล้ว, โฟลเดอร์ `/ (root)` → กด **Save**
4. รอสัก 1–2 นาที แล้วรีเฟรชหน้านั้น จะได้ลิงก์แบบ
   `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

ที่ root ของ repo มี 2 ไฟล์รองรับไว้แล้ว:

| ไฟล์ | ทำไมต้องมี |
|---|---|
| `index.html` | ตัวแอปอยู่ในโฟลเดอร์ `cs2-stats/` ไฟล์นี้เลยพา redirect เข้าไปให้อัตโนมัติ |
| `.nojekyll` | บอก Pages ว่าไม่ต้องเอาไฟล์ไปผ่าน Jekyll — เสิร์ฟไฟล์ตรง ๆ เร็วกว่า |

**ข้อควรรู้หลัง deploy**

- Pages เป็น **origin ใหม่** (`https://...github.io`) คนละที่กับตอนเปิดไฟล์ในเครื่อง
  → ข้อมูลใน localStorage **ไม่ตามไปด้วย** ให้ใช้ปุ่ม Export ที่เครื่องเดิม
  แล้ว Import เข้าที่เว็บใหม่
- เปิดจากมือถือได้เลย เข้าลิงก์แล้วกด "เพิ่มลงในหน้าจอโฮม" จะใช้เหมือนแอปเลย
- โฮสต์เป็นไฟล์นิ่ง ๆ ไม่มี server → **ข้อมูลยังอยู่แค่ในเครื่องที่เปิด** ไม่ได้ sync ข้ามเครื่อง
  และใครเปิดลิงก์ก็เห็นแค่ข้อมูลของตัวเอง
- repo เป็น public = ใครก็เปิดลิงก์ได้ (เห็นแค่หน้าเปล่า ไม่เห็นข้อมูลเรา)
  ถ้าอยากให้เป็น private ต้องใช้ GitHub Pro
